#### A. 外部控制 API（`src/api-control/`）

| 文件 | 行数 | 作用 |

架构是 **HTTP → SSE 浏览器桥 → WebRTC**：

```
第三方程序 -> HTTP /api/v1
           -> Vite 中间件
           -> SSE 推给已打开的浏览器页面
           -> App.joystickState / 20 Hz 控制循环
           -> rt/wirelesscontroller
           -> 现有 WebRTC 会话 -> Go2
```

关键点：

- 浏览器页面必须保持打开并已连上机器人；只跑 HTTP 服务不能让机器人动
- 没有认证、没有 token；有可达 Vite 端口的主机都能调用
- 控制权需要 `POST /api/v1/control/acquire` 获取
- 移动指令带 `ttl`（100–2000 ms，默认 500），超时自动失效
- 急停优先级最高
- API 动作只允许白名单内的动作栏命令

### 4.3 功能

- 手动移动：`vx/vy/vyaw`，服务端硬上限 `MAX_VX=0.50`、`MAX_VY=0.40`、`MAX_VYAW=1.00`
- 动作：站立、趴下、平衡站立、恢复、坐下、起立、握手、伸懒腰、比心、倒立、拜年、前跳、交叉步
- 倒立退出单独走 `/api/handstand/exit`，默认等待 3 秒
- 巡逻：1–20 步循环路径，支持定时移动、定距离、90°/180° 定角转向、等待；IMU 角度闭环纠偏；路径存 `patrol_path.json`
- 音频：AudioHub 上传 WAV、播放、暂停、列表、音量
- 视频：原装摄像头 MJPEG
- 状态：`/ws/state` 10 Hz 推送
- 健康检查：`/api/health`

接口前缀 `/api`：

页面：`/` 遥控、`/patrol` 巡逻、`/settings` 设置。

### 4.4 安全设计

- 拒绝跨来源和表单类 POST
- 同一浏览器按序号拒绝旧移动指令
- 持续移动期间拒绝其他浏览器抢占；停止操作任何人均可执行
- 最多 128 个控制会话
- 移动要求遥测数据新鲜，状态丢失时 watchdog 停止
- 0.40 秒未续传即停车
- `StopMove` 超时或返回 `-1` 时保留「待停止」状态并重试
- SDK `3104` 被明确解释为「等待应答超时」，不当作指令未执行

### 4.5 运行方式

```bash
cd ~/go2_web
export GO2_IFACE=eth0
bash start.sh
# start.sh 实际默认 0.0.0.0:8000（README 写的是 127.0.0.1）
```

`start.sh` 会：

1. source `/opt/ros/foxy/setup.bash`
2. source `~/unitree_ros2/cyclonedds_ws/install/setup.bash`
3. 设置 `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`
4. 把 `~/cyclonedds_ws/install/cyclonedds/lib` 放到 `LD_LIBRARY_PATH`，避免 `/usr/local/lib` 的 iceoryx 版本崩溃
5. 自动从 `192.168.123.x` 地址推断网卡
6. `uvicorn app:app --host 0.0.0.0 --port 8000`

注意：README 写默认监听 `127.0.0.1`，但 `start.sh` 的默认值是 `GO2_HOST=0.0.0.0`，会对全网段开放且没有认证。需要本机访问时显式设置 `GO2_HOST=127.0.0.1`。

README 提到部署到 `/opt/go2_web` 并安装 `go2-web.service`，但：

- `/opt` 下没有 `go2_web`
- 系统里没有 `go2-web.service`
- 当前没有 uvicorn 进程，8000 未监听

因此目前是手工运行状态。最后一次 RPC 日志为 2026-09-21 11:40。

## 8. 接手建议

1. **先做版本快照。** `unitree_ui` 和 `go2_web` 都没有 git。至少执行一次带日期的 tar 备份，或 `git init` 后提交当前状态。
2. **确认要保留哪套控制入口。** `unitree_ui` 功能全（SLAM、BLE、云端、3D），`go2_web` 更轻、直接走 DDS、巡逻/音频逻辑更贴近实际使用。两套同时维护成本高。
3. **外部 API 没有认证。** `/api/v1` 和 go2_web 都按「可信内网」设计。暴露到更大网络前必须加防火墙或反向代理认证。
4. **WiFi AP 链路需要硬件。** `unitree-webrtc-forward` 依赖 `wlan0`，当前没有无线网卡；确认原 USB 网卡是否还在。
5. **`go2_web` 的 systemd 部署未落地。** README 提到的 `go2-web.service` 在系统里不存在，`/opt/go2_web` 也没有。
6. **SDK trace 补丁是定制点。** 升级 SDK 时如果直接覆盖 `unitree_sdk2_python`，`go2_web/logs/rpc.log` 会消失。
7. **端口 4000 未确认。** 需要 root 权限才能看到属主；不要贸然占用或改动。
8. **远端时钟疑似不准。** 检查 NTP，否则日志时间、证书校验会受影响。
